# 일기 화면 구현

- 범위: `frontend/src/app/page.tsx`(홈=일기 목록), `frontend/src/app/diary/new/`, `frontend/src/app/diary/[id]/`, `frontend/src/lib/api.ts`
- 목표: 세션 유지 다음 단계로, "도메인 단위로 묶어서 진행" 절충안의 첫 배치 — 일기 CRUD 화면 전체
- 관련 문서: [프론트엔드 로그인 화면 구현](./06-프론트엔드%20로그인%20화면%20구현.md)

## 진행 내용

1. **`frontend/src/lib/api.ts` 신규**: `apiFetch(user, path, init)` 헬퍼 — Firebase `getIdToken()` + `Authorization` 헤더 부착을 공통화. 로그인 화면의 기존 인라인 fetch 코드도 이걸로 리팩터링(중복 제거)
2. **홈(`/`) = 일기 목록**: `GET /diary/me` 호출, 목록 렌더링 + "새 일기 쓰기" 버튼. 기존에 있던 "환영합니다" 화면을 대체
3. **`/diary/new`**: 작성 폼 — `entryType`(원라인/정식) 토글, `content`, `emoji`(선택), `privacyScope`(나만보기/전체공개)
4. **`/diary/[id]`**: 상세 조회 + 인라인 수정(`PATCH`) + 삭제(`DELETE`, `confirm()` 확인 후)

## 스코프에서 뺀 것

- **`privacyScope: 'group'` 옵션 미포함**: 그룹 목록 화면이 아직 없어서 groupIds를 고를 수단이 없음. 배치 2(그룹/친구)에서 그룹 화면 만든 뒤, 일기 작성/수정 폼에 그룹 선택 옵션을 추가하는 걸로 미룸 (백엔드 `UpdateDiaryDto`도 애초에 `privacyScope`를 `'group'`으로 바꾸는 걸 지원 안 함 — 별도 공유 API 필요, 기존에 알려진 제약)
- **오늘의 프롬프트(`GET /diary/prompt/today`) 미연동**: 작성 화면에 프롬프트 제안을 보여주는 건 이번 배치 범위 밖

## 검증

- `tsc --noEmit`, `eslint` 클린
- 실제 브라우저(Claude in Chrome)로 목록 조회 → 작성 → 상세 이동 → 수정까지 end-to-end 확인 (기존 Postman 테스트로 만들어둔 일기도 목록에 정상 표시됨 — 백엔드 데이터와 프론트가 제대로 맞물림)
- **삭제는 라이브 클릭 테스트 안 함**: `confirm()` 네이티브 다이얼로그를 띄우는 코드라 브라우저 자동화로 클릭하면 확장이 멈춤. 코드 자체는 다른 화면에서 이미 검증된 `apiFetch` DELETE 패턴 그대로라 단순함
