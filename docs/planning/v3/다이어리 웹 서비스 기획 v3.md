## **`PROJECT TOPIC`**

‘Instagram’과 같이 사진 중심 SNS의 피로감을 줄이고, 텍스트와 진솔한 기록에 집중하며 AI 감성 기능과 그룹 별 공유 권한을 제공하는 감성 소셜 다이어리 서비스. 메인 기능은 개인 다이어리이며, 부가 기능으로 그룹 멤버 간 실시간 소통(QnA/채팅)을 지원해 소속감을 더한다.

## **`PROJECT OVERVIEW`**

- 기획 배경 : 기존 ‘인스타그램’ 등 화려한 이미지 중심 SNS에서 벗어나, 글과 기록 본연에 집중할 수 있는 공간을 제공하고자 함. 다만 텍스트 중심 기록은 진입장벽이 높다는 한계가 있어, '셋로그(Setlog)' 등 저부담 기록 앱의 흥행 요인(낮은 진입장벽, 그룹 동기화 기록 경험)을 참고하여 보완함.
- 핵심 컨셉 :
    - 인스타그램 형태의 익숙한 피드 레이아웃
    - **메인은 일기 다이어리**, 그룹 소통(QnA/채팅)은 부가 기능
    - 텍스트 중심의 기록 + 보조적 미디어(사진/영상) 첨부
    - 세분화된 프라이버시/공유 설정
    - AI를 활용한 감성 케어 및 요약 기능
    - 낮은 진입장벽의 초간단 기록 옵션 (원라인 모드 / AI 질문 프롬프트)
    - **인스타 스토리형 그룹 QnA + 그룹 채팅**을 통한 실시간 소통 및 공동체 경험 제공 — 앱 내 노출명 **"Dialog"**

## **`CORE FEATURES`**

### 1. 일기 작성 및 미디어 첨부 (Contents)

- 텍스트 중심 작성 : 짧은 메모부터 긴 일기까지 글 중심으로 자유롭게 작성.
- 미디어 첨부 : 글의 감성과 추억을 기억하는데 보완할 수 있는 이미지 및 짧은 동영상 업로드 지원.
- **⚡ 원라인 모드 (Quick Log):**
    - 홈 피드 상단 고정 입력바에서 이모지 선택 + 한 줄 텍스트만 남겨도 정식 일기로 카운트
    - **이어쓰기**: 아침에 남긴 원라인을 이후 다시 열어 내용을 덧붙여 긴 일기로 발전시킬 수 있음 — "가볍게 시작해서 원하면 깊이 쓰는" 흐름으로 진입장벽을 낮추는 핵심 장치
    - **기록 일수 카운터 (Light Streak)**: "N일 기록했어요" 형태의 비압박형 카운터만 제공. 연속 끊김에 대한 페널티, 경고, 랭킹/배지 등 경쟁·손실 유발 요소는 넣지 않음 — 습관화 효과는 살리되 서비스의 감성/힐링 톤과 "SNS 피로감 탈피" 취지를 해치지 않도록 함
- **💬 AI 질문 프롬프트 (Guided Entry, 개인용):**
    - 매일 지정 시간에 짧은 질문(예: "오늘 가장 웃겼던 순간은?", "오늘 누군가에게 고마웠던 일은?")을 푸시 알림으로 발송, 답변만 하면 일기 완성
    - MVP 단계는 정적 질문 뱅크(요일/계절별 로테이션)로 시작, 이후 최근 일기 패턴을 분석한 AI 개인화 질문으로 고도화
    - 질문은 메타데이터로 함께 저장되어 이후 AI 요약 리포트와도 연동 가능
    - ※ 4번 항목의 "그룹 QnA"와는 별개 기능(개인 대상 vs 그룹 대상)이므로 UI상 명확히 구분

### 2. 친구 및 그룹 관리 (Friend & Group Management)

- **친구 추가**: 초대 링크 공유 방식으로 통일 (전화번호 검색·연락처 매칭 인프라 없이 구현) — 링크로 친구 요청을 보내고 상대가 수락하면 친구 목록에 추가됨
- **그룹 생성**: 그룹장이 그룹을 만들면 고유 초대 코드/링크가 자동 발급되며, **코드를 아는 사람은 누구나 별도 승인 절차 없이 코드 입력만으로 즉시 그룹에 참여** 가능
- **초대 코드 만료**: 발급된 코드는 지정된 시간(예: 24시간)이 지나면 자동으로 파기되어 더 이상 사용할 수 없음 — 만료 후에는 그룹장이 새 코드를 재발급해야 참여 가능
- **그룹 = 단일 엔티티**: 일기 공유(3번 프라이버시 설정의 "그룹별 선택 공유")와 그룹 QnA/채팅(4번)이 동일한 그룹을 공유함 — 그룹을 하나 생성하면 일기 공유 대상 지정과 QnA/채팅 참여가 동시에 가능해짐
- **그룹장 권한**: 초대 코드 재발급(만료 전 수동 재발급도 가능), 멤버 강제 탈퇴, 그룹 이름/설정 변경
- **멤버 권한**: 그룹 탈퇴, 그룹 내 QnA/채팅 참여, 그룹을 자유롭게 일기 공유 대상으로 지정 (그룹장 별도 승인 불필요)

### 3. 세분화된 공유 권한 설정 (Privacy Control)

- 🔒나만보기 (Praivate): 나만 접근 가능한 완전한 개인 비밀 공간
- 👥전체 공유 (Public/Friends): 내 친구 목록 전체에 공개되는 피드
- 👪그룹별 선택 공유 (Group): 2번에서 생성/참여한 그룹 중 지정한 그룹 멤버에게만 제한적으로 피드 공개
- ※ 아래 4번 "그룹 QnA/채팅"은 이 프라이버시 체계와 별도 카테고리로 동작함(항상 그룹 내 공개, 개별 비공개 전환 불가)

### 4. Dialog — 그룹 실시간 소통 (QnA & 채팅)

일반 일기와는 분리된 별도 공간으로, 그룹 멤버 간 가벼운 실시간 소통에 집중한다. 앱 내에서는 **"Dialog"**라는 이름으로 노출되며, QnA(스토리형 질문·답변)와 채팅 두 하위 기능으로 구성된다. (참고: 프로젝트 코드네임 `monolog`와 짝을 이루는 네이밍 — 혼자 쓰는 기록(모노)과 함께 나누는 대화(다이얼로그)의 대비)

- **그룹 QnA (인스타 스토리 / 셋로그 느낌):**
    - 그룹 멤버 누구나 원하는 시간에 공통 질문을 올릴 수 있음(AI가 아닌 멤버 자율 등록)
    - 질문 등록 시 그룹 전원에게 푸시 알림 발송 → 실시간으로 답변 작성 가능
    - 답변에는 텍스트뿐 아니라 **사진 첨부 가능** (텍스트 위주 피로감 해소)
    - **AI 질문 추천**: 멤버가 직접 질문을 쓰기 어려울 때, 시간대 기반으로 AI가 질문을 추천 (예: 12시 → "오늘 점심 뭐 먹었어?", "오늘 학식 뭐야?")
    - 인스타 스토리처럼 **48시간 경과 시 자동 삭제(Soft Delete)** — 원하는 답변/질문은 사용자가 개별 저장 가능
    - 프라이버시 설정과 무관하게 항상 그룹 내 전원 공개
- **그룹 채팅:**
    - 그룹 단위 채팅방 제공 (1:1 채팅은 제외, 그룹 채팅만 지원)
    - QnA에서 이어진 대화를 자유롭게 확장할 수 있는 커뮤니케이션 채널

### 5. AI 기반 차별화 기능 (AI Integration)

- **🎵 AI 감성 음악 추천:**
    - 작성된 일기의 텍스트와 감정 톤을 AI가 분석
    - 일기 분위기와 잘 어울리는 음악(BGM/곡)을 자동 추천
- **📊 AI 주별 / 월별 회고 요약:**
    - 일주일 또는 한 달 동안 쌓인 일기 데이터를 분석
    - 무슨 일이 있었는지 주요 사건과 감정 흐름을 한눈에 보기 좋게 요약 리포트로 생성
- **📝AI 제목 추천:**
    - AI가 일기 내용을 바탕으로 적절한 제목을 추천해줌
    - 여러가지 옵션을 주고 선택 및 수정가능.
- **🖼️ AI 커버 일러스트 생성 (온디맨드):**
    - 사진이나 동영상을 첨부하지 않고 글만 쓴 날, 어울리는 감성의 수채화/미니멀 일러스트 커버 이미지를 생성
    - **자동 생성이 아닌 사용자가 "생성" 버튼을 눌러야 실행**되는 온디맨드 방식 (원라인 모드처럼 매우 짧은 글에도 매번 자동 호출되어 비용이 낭비되는 문제 방지)
    - **임시저장 & 이탈 방지**: 작성 중 업로드/생성 버튼을 누르지 않고 화면을 벗어나려 하면 팝업으로 임시저장 여부를 확인 → 이어쓰기 시 임시저장된 내용 복원
    - 이어쓰기로 내용이 바뀐 뒤에도 "생성" 버튼을 다시 누르면 새 이미지가 생성되므로 별도의 재처리 정책이 불필요함
    - **개발 포인트**: 이미지 생성 AI API(예: DALL-E, Stable Diffusion 등) 연동 경험과, 생성된 이미지를 클라우드 저장소에 저장하고 캐싱하는 프론트/백엔드 로직을 익힐 수 있다.
- **🔒 타임락(Time-Lock) 일기 & 프라이빗 보안 미디어:**
    - "이 일기는 2027년 1월 1일에 공개됩니다"처럼 특정 미래 시점에 지정된 친구나 그룹에게만 열리는 미래 일기/타임캡슐 기능
    - 나중에 클라우드 네트워크에 올릴 때, '나만 보기'나 '타임락'이 걸린 미디어 파일(이미지/영상)에 대해 비인가자가 URL만 복사해서 들어오는 것을 막는 **보안 URL(Presigned URL)** 기법을 적용

### 6. 알림 설정 (Notification Control)

- 알림 종류별(개인 AI 질문 프롬프트 / 그룹 QnA / 그룹 채팅) 개별 on/off 토글 제공
- 전체 알림 일괄 끄기 옵션도 별도 제공
- "SNS 피로감 탈피"라는 서비스 취지에 맞춰, 알림이 쌓이는 것에 대한 사용자 통제권을 기본으로 보장

## **`SCREEN STRUCTURE`**

1. **메인 화면**: 일기가 모여 있는 피드 (기존 기획 그대로)
2. **친구/그룹 관리 화면**: 친구 목록·초대 링크 공유, 그룹 생성·초대 코드 발급·멤버 관리
3. **AI 요약 화면**: 한 달/한 주를 AI가 요약해주는 리포트 화면
4. **Dialog - QnA 화면**: 공통 질문에 답변을 공유하는 화면 (인스타 스토리 / 셋로그 느낌)
5. **Dialog - 채팅 화면**: 그룹별 채팅 (1:1 제외)
6. **설정 화면**: 알림 카테고리별 on/off 제어

## **`TECHNICAL POINT`**

- **프론트엔드 (FE):**
    - 텍스트 피드 중심의 깔끔하고 감성적인 UI/UX
    - 드래그 앤 드롭 미디어 업로드 및 비동기 데이터 처리
    - 홈 피드 상단 고정 원라인 입력바 UI, 이어쓰기 편집 흐름
    - 편집 화면 이탈 감지 및 임시저장 확인 팝업(Draft 복원 포함)
    - 스토리형 QnA UI (48시간 만료 카운트다운, 저장 인터랙션)
    - 실시간 채팅 UI
    - 초대 링크/코드 딥링크 처리 UI (친구 요청, 그룹 참여)
    - 그룹/친구 관리 화면 UI (그룹 생성 폼, 초대 코드 발급·재발급·만료 표시, 멤버 목록 관리)
    - 알림 설정 화면 UI (카테고리별 on/off 토글)
- **백엔드 (BE) & 데이터베이스 (DB):**
    - 일기별/그룹별 접근 권한을 엄격하게 통제하는 권한 제어(RBAC) 로직
    - 회원, 일기, 그룹, 미디어 간의 효율적인 DB 관계(Relational) 설계
    - 그룹 엔티티(`group_id`, 이름, 그룹장, 초대코드, 코드 발급시각, 코드 만료시각(TTL)) 및 그룹-멤버 매핑 테이블(역할: 그룹장/멤버) 설계 — 일기 공유와 QnA/채팅이 동일 그룹 엔티티를 참조
    - 초대 코드 만료 검증 로직 — 참여 요청 시점에 만료시각과 비교해 무효화 처리(별도 배치/크론 작업 불필요, 조회 시점 검증만으로 충분)
    - 친구 관계 엔티티(요청/수락 상태) 및 초대 링크 토큰 발급·검증 로직
    - 일기 엔티티에 `entry_type(quick/full)` 구분 필드, 질문 프롬프트 메타데이터 연동
    - 일기 임시저장(Draft) 엔티티/로직
    - 그룹 QnA 엔티티 설계(`group_id`, 작성자, 질문/답변, 사진첨부, 생성시각, 만료시각(48h), `soft_delete` 플래그, 사용자별 개별 저장 여부) — 프라이버시 체계와 분리된 별도 접근 로직
    - 그룹 채팅을 위한 실시간 메시징 인프라(WebSocket 등) 및 채팅방-그룹 매핑
    - **정기/실시간 알림 발송 스케줄링 인프라** — 1단계(개인 AI 질문 프롬프트)부터 필요하며, 2단계(그룹 QnA·채팅 알림)에서 확장
    - 사용자별 알림 설정(카테고리별 on/off) 엔티티 및 발송 전 설정 체크 로직
    - AI 커버 일러스트는 온디맨드 호출 방식으로 설계(자동 배치 작업 불필요)
    - LLM/AI API 연동 및 프롬프트 엔지니어링

## **`TECH STACK`**

**팀 구성**: 본인(FE + BE) / 팀원(AI 파트). AI 기능을 **독립된 서비스로 분리**해서, 팀원이 AI 로직을 바꿔도 본인의 BE 배포에 영향이 없고 병렬 개발이 가능하도록 구성한다.

```
[FE: Next.js] ──REST/WebSocket──▶ [Core BE: NestJS] ──내부 REST──▶ [AI Service: FastAPI]
                                        │
                                   [PostgreSQL / Redis / S3]
```

**BE ↔ AI 서비스 API 계약** (병렬 개발을 위해 가장 먼저 합의할 항목)

```
POST /ai/title            { diary_text } → { title_options: string[] }
POST /ai/music             { diary_text } → { mood_tag, track_suggestions[] }
POST /ai/summary           { entries[] } → { summary_report }
POST /ai/cover-image        { diary_text } → { image_url }
POST /ai/qna-suggestion    { time_of_day } → { question }
```

이 계약을 먼저 확정하면, 본인은 목(mock) 응답으로 Core BE·FE를 먼저 완성하고, 팀원은 동시에 실제 LLM 연동(OpenAI GPT-4o-mini + DALL-E 3, 음악은 감정 태그 → Spotify Web API 매핑)을 독립적으로 개발할 수 있다.

## **`ROADMAP`**

- **1단계 (MVP):** 회원가입, 텍스트/미디어 일기 작성, 원라인 모드 + 정적 질문뱅크 기반 AI 질문 프롬프트(진입장벽 최소화 우선 검증, 알림 스케줄링 인프라 최초 구축), 알림 카테고리별 on/off 설정, 친구 추가 및 그룹 생성/초대 코드(그룹 기반 기능의 선행 인프라), 3종 공유 권한(나만보기/전체/그룹) 구현, AI 제목 추천, 타임락 일기 & Presigned URL 보안 미디어(권한 설계와 함께 구축)
- **2단계 (그룹 소통):** 그룹 QnA(실시간 질문/답변, 사진 첨부, 48시간 소프트 삭제, AI 시간대 질문 추천) + 그룹 채팅 — 그룹 권한 체계 위에 구축, 알림 인프라 확장
- **3단계 (AI 연동):** 일기 작성 시 AI 감성 음악 추천 API 연동
- **4단계 (고도화):** 주별/월별 AI 요약 리포트 생성 기능 추가 및 UI 최적화
- **5단계 (심화):** AI 커버 일러스트 생성 기능 — 온디맨드 버튼 방식(이미지 생성 API 연동 및 클라우드 저장/캐싱)

## **`CHANGE LOG (v2 → v3)`**

`다이어리 기획 v2 검토 이슈.md`의 결정사항을 반영:

1. AI 커버 일러스트 생성 → 자동에서 **사용자 트리거(버튼) 방식**으로 변경, 이탈 시 임시저장 팝업 추가
2. 그룹 소통 기능 → 프라이버시 체계와 **분리된 별도 카테고리**로 재정의
3. 스트릭(연속 기록일수) 시스템 → **비압박형 "기록 일수 카운터"로 확정** (페널티/랭킹 없는 가벼운 버전, 서비스 톤 유지 우선)
4. AI 자동 생성 기능들(음악/요약) → 기존 방향 유지(자동 생성)
5. 알림 스케줄링 인프라 → 로드맵 1단계 설명에 명시적으로 포함
6. "이어쓰기" 후 AI 생성물 재처리 정책 → 온디맨드 생성 방식 도입으로 이슈 자체가 해소됨
7. **그룹 위클리 체크인 컨셉을 전면 재설계**: 시스템 주도 정기 발행 + 동시공개잠금 방식 → 멤버 자율 등록 + 실시간 답변 + 48시간 후 소프트 삭제(인스타 스토리/셋로그 스타일) 방식으로 변경. 그룹 채팅 기능 신규 추가.
8. **친구 추가 및 그룹 생성 방식 신규 정의**: 카카오톡식 연락처 검색 대신 **초대 코드/링크 기반**으로 통일(구현 부담 최소화, 폐쇄형 그룹 특성에 부합). 일기 공유용 그룹과 QnA/채팅용 그룹이 **동일한 단일 그룹 엔티티**임을 명확화.
9. **알림 설정(카테고리별 on/off) 기능 신규 추가**: 개인 AI 질문 프롬프트·그룹 QnA·그룹 채팅 알림이 3중으로 쌓이는 문제를 방지하고, "SNS 피로감 탈피"라는 서비스 톤과의 일관성을 확보하기 위해 1단계 MVP부터 포함.
10. **초대 코드 방식 구체화**: 코드 입력 시 승인 절차 없이 누구나 즉시 그룹 참여 가능하도록 확정, 코드에 유효시간(TTL)을 부여해 특정 시간 경과 후 자동 파기 — 이후 그룹장 재발급 필요.
11. **그룹 내 일기 공유 권한 단순화(B안 확정)**: "그룹장 허가 시에만 일기 공유 가능" 규칙 삭제, 그룹 멤버는 누구나 자신이 속한 그룹에 자유롭게 일기 공유 가능 — 별도 엔티티 필드·승인 UI 불필요, 기존 그룹 엔티티 설계와 그대로 정합.
12. **프로젝트/기능 네이밍 확정**: 프로젝트명 `monolog`(개인 다이어리=혼자 쓰는 기록), 그룹 QnA & 채팅 통합 기능의 앱 내 노출명 `Dialog`(그룹=함께 나누는 대화)로 확정. 메인/부가 기능 구조를 이름 자체로 드러냄.

## **`최종 정리 요약`**

**한 줄 정의**: 사진 대신 글로 진솔하게 기록하는 개인 다이어리를 메인 기능으로, 그룹 멤버와의 가벼운 실시간 소통(QnA·채팅)을 부가 기능으로 결합한 감성 소셜 다이어리 서비스.

**네이밍**: 프로젝트명 `monolog`(혼자 쓰는 개인 기록) — 그룹 QnA/채팅 기능은 앱 내에서 `Dialog`(함께 나누는 대화)로 노출. 두 이름이 "혼자(모노) ↔ 함께(다이얼로그)"라는 서비스의 메인/부가 기능 구조를 그대로 반영한다.

**핵심 기능 구성 (CORE FEATURES 1~6)**

1. **일기 작성** — 텍스트/미디어 자유 작성 + 원라인 모드(진입장벽 최소화, 이어쓰기, 비압박형 기록 카운터) + 개인용 AI 질문 프롬프트
2. **친구/그룹 관리** — 친구는 초대 링크, 그룹은 초대 코드(TTL 만료) 방식으로 승인 절차 없이 개방형 참여
3. **프라이버시 설정** — 나만보기 / 전체 공유 / 그룹별 선택 공유 3종을 일기 단위로 자유롭게 설정
4. **Dialog (그룹 QnA & 채팅)** — 멤버가 원할 때 질문 등록 → 실시간 답변, 48시간 후 소프트 삭제, 프라이버시 체계와 분리되어 항상 그룹 전원에게 공개
5. **AI 통합** — 음악 추천/요약 리포트는 자동 생성, 커버 일러스트는 비용 관리를 위해 온디맨드, 타임락 + Presigned URL로 미디어 보안 확보
6. **알림 설정** — 카테고리별(개인 질문·그룹 QnA·그룹 채팅) on/off 및 전체 끄기 제공

**설계상 핵심 원칙**

- 일기와 그룹 QnA/채팅은 프라이버시 체계가 **완전히 분리**됨 — 일기는 사용자가 매번 선택, QnA/채팅은 항상 그룹 전원 공개로 고정
- 그룹은 일기 공유용과 QnA/채팅용이 **하나의 동일한 엔티티**를 공유
- AI 기능 중 비용이 큰 이미지 생성만 온디맨드로 제어하고 나머지는 자동 생성 유지
- 습관화 장치(원라인 모드, 기록 카운터)는 두되 경쟁·손실 유발 요소(랭킹, 페널티)는 배제 — "SNS 피로감 탈피"라는 브랜드 톤을 모든 기능 설계의 우선순위로 둠
